# ⚡ ЕНТ-Спринт: 80/20

Двуязычный (RU/KZ) сайт для подготовки к ЕНТ по принципу Парето:
**20% ключевых тем дают 80% результата**. Сервера нет: профиль ученика и весь
прогресс живут в `localStorage` браузера. Mobile-first, тёмная тема по
умолчанию и светлая в один клик, живой интерфейс (стекло, градиенты,
наклон карточек) с уважением к `prefers-reduced-motion`.

## Запуск

Нужен только браузер + любой статический сервер (ES-модули не работают по `file://`):

```bash
# вариант 1: Node
npx serve .            # затем открыть http://localhost:3000

# вариант 2: Python
python -m http.server 8123   # затем открыть http://localhost:8123

# вариант 3: Windows PowerShell (без Node и Python)
powershell -ExecutionPolicy Bypass -File dev-server.ps1
# затем открыть http://localhost:8123
```

Либо откройте папку в VS Code и используйте Live Server.

## Формат ЕНТ (в js/config.js)

* 120 заданий, максимум 140 баллов, 4 часа.
* Обязательные: История Казахстана (20), Грамотность чтения (10), Математическая грамотность (10).
* Профильные: по 40 заданий каждый.
* 12 комбинаций + режим «Творческий экзамен» (без профильных, только советы и ресурсы).

Все цифры — настройки: поменяли спецификацию → поправили `EXAM`, `MANDATORY`,
`PROFILE_QUESTIONS`, `COMBOS` в `js/config.js`. Пороги поступления правятся и прямо
в интерфейсе (Профиль → Настройки), значения по умолчанию в `DEFAULT_THRESHOLDS`.

## Профиль ученика (вход по номеру)

Сервера нет, поэтому «вход» — это разделение прогресса между учениками за одним
планшетом, а **не защита данных**. Никто не проверяет код-пароль снаружи: любой,
у кого есть доступ к браузеру, может прочитать `localStorage` руками. Об этом
же честно пишет плашка на экране входа.

Как устроено:

| Ключ | Что хранит |
|---|---|
| `ent-sprint-device` | язык и тема — одни на устройство, чтобы экран входа говорил на языке пользователя |
| `ent-sprint-auth` | список аккаунтов `{имя, соль, хеш, дата}`, активный номер, отметка `migratedFrom` |
| `ent-sprint-p:<11-значный номер>` | весь прогресс одного ученика: комбинация, баллы, статистика, ошибки, пробники |
| `ent-sprint-v1` | старый «безобщий» прогресс — не удаляется, чтобы откат был возможен |

* Номер нормализуется к формату `7701XXXXXXX`: принимаются `8` и `+7` в начале,
  скобки, пробелы и дефисы. Работает только казахстанский формат (`8`/`7` +
  10 цифр) — интернациональные номера пока не поддерживаются.
* Код-пароль — 4–8 цифр. Хранится как PBKDF2-SHA256, 150 000 итераций,
  случайная соль 16 байт на аккаунт, в открытом виде PIN нигде не остаётся.
  Нужен «безопасный контекст»: `https://` или `localhost`. При `file://`
  `crypto.subtle` недоступен и регистрация вежливо вернёт ошибку.
* Первый созданный профиль получает старый прогресс из `ent-sprint-v1`
  (флаг `migratedFrom` ставится один раз, сам ключ остаётся нетронутым).
* «Сбросить прогресс» в профиле удаляет только ключ текущего ученика;
  язык, тема и остальные профили не трогаются.

## Оформление и движение

Тёмная тема — по умолчанию, светлая переключается кнопкой в шапке
(обе — набор CSS-переменных на `body[data-theme]`, см. начало `css/style.css`).

* **Живой фон.** Три размытых цветных пятна дрейфуют с разными периодами
  (26/34/41 с), поверх них — полупрозрачная вуаль, без которой стекло карточек
  теряет контраст. Слои лежат в `.fx` (`z-index:-1`), поэтому просвечивают
  сквозь `backdrop-blur` карточек.
* **Шлейф за курсором** (`#cursorGlow`) догоняет мышь через
  `requestAnimationFrame` с линейной интерполяцией и засыпает, когда курсор
  стоит.
* **3D-наклон карточки** — до ±9°, плюс блик, следующий за курсором
  (`--mx`/`--my`). Вешается только при `(hover: hover) and (pointer: fine)`,
  то есть на телефоне его нет и батарея не тратится.
* **Появление при скролле** — `IntersectionObserver` добавляет `.in` с
  лесенкой задержек; анимация идёт по очереди, а не всем экраном сразу.
* **Hero** на Главной и на входе — крупная типографика с градиентной заливкой
  текста, строки въезжают по одной.
* Всё это выключается, если в системе включён «уменьшить движение»
  (`prefers-reduced-motion`): карточки сразу видимы, пятна и шлейф не рисуются.
  Страховка от сломанного JS та же: класс `.js-motion` вешает `js/motion.js`,
  без него `opacity: 0` к карточкам не применяется.

## Как добавлять контент

### Новый вопрос / карточка
Откройте `js/data/subjects/<предмет>.js`. Каждый вопрос:

```js
{
  id: 'mt-q11',                       // уникальный в рамках файла
  topic:  { ru: '...', kz: '...' },   // микро-тема для фильтров спринта
  text:   { ru: '...', kz: '...' },
  options:{ ru: ['A','B','C','D'], kz: ['A','B','C','D'] }, // ровно 4 варианта
  answer: 0,                          // индекс верного: 0=A, 1=B, 2=C, 3=D
  explain:{ ru: 'разбор на пальцах', kz: 'қарапайым талдау' },
  draft: true,                        // пока не сверено со спецификацией НЦТ

  // оба поля необязательные; без них задание — одиночный выбор без уровня
  type: 'multiple',                   // 'multiple' = несколько верных ответов
  difficulty: 'A',                    // 'A' | 'B' | 'C' — уровни по спецификации
  // для 'multiple' answer становится массивом: answer: [0, 2]
}
```

Карточка: `{ id, title:{ru,kz}, back:{ru,kz}, draft:true }`.

Проверка ответа (включая «нет частичного балла» для множественного выбора) — в
`js/core/qtype.js`; и спринт, и пробник берут её оттуда, поэтому новое поле
`type` не требует правок в раннерах.

### Новый предмет
1. Скопируйте любой файл из `js/data/subjects/` как шаблон.
2. Поменяйте `id`, `icon`, `name`, контент.
3. Подключите его в реестре `js/data/subjects.js`.
4. Если предмет профильный и участвует в комбинациях — добавьте комбинацию
   в `COMBOS` (js/config.js).

### Новый ресурс
Добавьте объект в `js/data/resources.js` (см. комментарии).
Правило проекта: **ссылки только реально существующие**. Если точного адреса нет —
ставьте `url: null`: на сайте появится плашка «Ссылку добавить вручную».

### Переводы
Все строки интерфейса — в `js/i18n/ru.js` и `js/i18n/kz.js` (одинаковые ключи).

`ok: true` и обновите дату проверки в комментарии над массивом `OFFICIAL`.

Что осталось расхождением с официальной структурой теста:

- **Формат заданий.** Спецификация профиля: 25 одиночного выбора + 5 множественного
  выбора + 5 на соответствие + 5 на понимание условия (контекст), сложность
  А/В/С = 50/30/20. Модель вопроса поддерживает первые два формата: поле
  `type: 'multiple'` (answer — массив индексов, частичного балла нет) и
  `difficulty: 'A'|'B'|'C'`; логика проверки вынесена в `js/core/qtype.js`,
  интерфейс — в спринте и пробнике. Соответствие и контекст пока не modeled:
  они требуют другой структуры задания, поэтому 10 заданий из 40 не
  тренируются.
- **Минимумы по блокам.** Порог правильных ответов по каждому блоку задан в
  `BLOCK_MINIMUMS` (история Казахстана ≥5, ГЧ и МГ ≥3, любой профильный ≥5) и
  показывается в итоге пробника: если блок не набран, результат аннулируется
  независимо от общего балла.
- **Задания с текстом.** Для «Оқу сауаттылығы», казахской и русской литературы,
  математической грамотности по спецификации нужны отрывки текста-основы; сейчас
  это вопросы без текста.
- **Литература.** Многие авторы и произведения в `kazlit.js` / `ruslit.js` не
  входят в официальный перечень («Қара сөз», «Құлагер», «Алпамыс»,
  Булгаков, Шолохов, «Отцы и дети», «Вишнёвый сад», «Анна Каренина»). Список
  пока сверялся только по названию перечня, сами перечни — длинные PDF,
  и точная сверка требует построчного чтения.
- **Покрытие тем.** По каждому предмету затронута малая часть тем из
  тематического анализа; парето-приоритет по разделам с наибольшим числом тем
  пока рассчитывается вручную пользователем.

Отдельная предосторожность: текст `100 дат (2027)` при извлечении из PDF
(`pdftotext -layout`) теряет выравнивание двух колонок, поэтому пары
«дата → событие» из этого `.txt` нельзя использовать как источник истины без
визуальной проверки PDF в читалке.

## Технологии

Vanilla JS (ES-модули), без сборщика и зависимостей. Данные — обычные JS-файлы
(`export default {...}`): их можно держать в JSON-подобном виде и по желанию
перевести в fetch-загрузку `.json` без изменения логики страниц.
